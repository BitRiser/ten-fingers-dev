# Проверка безопасности — 8 октября 2026

Проверена статическая версия v5.9: исходники, Git-история, обработка пользовательских текстов и резервных копий, сетевые обращения и браузерная политика. Это ограниченная проверка кода и поведения, а не гарантия отсутствия уязвимостей и не полноценный внешний пентест.

## Проверено и исправлено

- В 20 коммитах и 261 уникальном объекте Git не обнаружены проверенные шаблоны GitHub/OpenAI/AWS-токенов и приватных ключей. Проверка по шаблонам не обнаруживает любые возможные секреты.
- Пользовательские строки в редакторе и карточках экранируются; учебный код отображается, не исполняется.
- Импорт резервных копий отклоняет `__proto__`, `constructor`, `prototype`, некорректные настройки, чрезмерные объёмы и несовместимые профили. Восстановление предыдущей локальной копии теперь проходит ту же проверку.
- Добавлена Content Security Policy: JavaScript только с текущего сайта, запрет inline-скриптов и eval, объектов и подмены базового URL. Для динамического оформления разрешены inline-стили. Не добавляй сторонний JavaScript без пересмотра политики.
- Функция объяснения запуска из файла вынесена в `boot.js`; она создаёт элементы через `textContent`.
- Добавлен `no-referrer`; локальный сервер отдаёт `X-Content-Type-Options: nosniff`. Доступ локального сервера ограничен `127.0.0.1`.
- Файлы баз данных, приватные ключи и `.env` исключены из будущих коммитов.
- Аудио загружается только с текущего сайта. Сторонних трекеров и отправки набранных текстов нет.

## Границы текущей версии

Прогресс и тексты хранятся в браузере. Это не защищённая серверная база: пользователь и другой код на том же origin могут изменить локальные данные. Локальный прогресс не следует считать доверенным основанием для публичного рейтинга. На общем компьютере доступ к тому же профилю браузера означает доступ к локальным текстам.

В приложении ещё нет собственного сервера регистрации и паролей или синхронизации аккаунтов. Доступ опубликованного Sites проекта регулируется Sites; текущая аудитория custom сохранена. Проверка не заявляет безопасность отсутствующих механизмов входа, сессий и базы.

Для следующего серверного этапа: хеши Argon2id вместо открытых паролей, защищённые HttpOnly/Secure cookie, защита CSRF, ограничения попыток входа, авторизация каждой записи по владельцу, параметризованный SQL, HTTPS, резервные копии и проверка восстановления. Пароли и хеши не должны попадать в таблицу общего доступа, браузер, Git или журналы. Требования сверены с [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html) и [OWASP Authentication](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html).

Перед публичной регистрацией отдельно проверить изоляцию двух пользователей, перебор паролей, истечение/отзыв сессий, выход, CSRF и обработку больших запросов. Выбор входа и места хранения данных пока ожидает ответа владельца.

Код дополнительных звуков является только клиентским переключателем функции. Хеш проверяется в браузере; код можно подобрать или обойти изменением клиентского состояния. Аудиофайлы остаются статическими ресурсами. Эта функция не защищает аккаунты, личные данные или сервер.
